# auto模型切换
为 AstrBot 提供固定的auto模型，在同一个key切换分组后自动匹配新模型。
也就节省几十秒。

## 使用
加载后自动注册auto模型，AI那边需要手动配置一次。
在配置界面填个API和key，优先级缺什么手动填。

上游需要支持 OpenAI 兼容的 `/v1/models` 和 `/v1/responses` 接口。
插件默认监听 `127.0.0.1:56751`，需要该端口空闲，且运行 AstrBot 的账户具有绑定权限。

监听端口可通过 `listen_port` 配置（默认 `56751`，范围 1～65535）；修改后重载插件或重启 AstrBot，插件自动更新自己创建的本机供应商地址。

## 外部访问与路由

- `允许外部访问` 默认关闭；开启后监听 `0.0.0.0`，客户端基础地址为 `http://公网IP:端口/v1`，需放行服务器对应端口。
- `访问密钥` 与上游 `key` 独立；开启外部访问且留空时自动生成并保存。外部请求在 `Authorization: Bearer <访问密钥>` 中携带，本机直连免密。公网使用建议通过 HTTPS 反向代理；代理应监听独立地址，不要把未鉴权请求转发到本机免密端口。
- `GET /v1/models` 返回 `auto` 和上次成功获取的全部上游模型。所有刷新共用一秒间隔，进行中的查询也共用；失败保留旧列表、当前模型和不存在记录，无定时查询。
- 列表查询成功后检查当前模型；仍存在则保留，缺失或为空才按优先级及兜底规则选择。自动补选只追加模型名，省略上下文默认 100000。
- 请求名称 `auto` 使用当前自动模型；其他名称原样转发上游，不要求先获取列表或匹配缓存，大小写保持不变。
- 上游明确返回模型不存在或当前分组无可用渠道时，记录该名称并回退 auto；以后同名请求直接走 auto。成功刷新模型列表后清除这些内存记录，允许重新尝试原名称。
- 首次确认指定模型不存在时，回退前先按一秒合并规则刷新列表，避免继续使用旧分组的 auto；查询失败仍可尝试原缓存。若新列表仍无该指定名称，保留本次不存在记录到下次成功刷新。
- 当前注册的备用名称也作为本地自动别名，不向上游额外尝试一次。
- 模型列表中的自动别名使用当前模型的上下文长度；指定模型按各自的优先级配置返回，未列入优先级的上游模型不提供 `context_window`。
- 鉴权、限流、连接故障和普通服务错误不会被记作模型不存在；指定模型遇到这些错误直接返回。
- 工具、输入等其他参数的错误不作为模型不存在；自动兜底筛除明确的音频、实时语音等专用模型，手动优先级不受此限制。
- auto 当前模型为空时初始化选择；首次会话响应明确为模型不可用时才刷新和选择，只有实际模型改变才重试。每个会话最多发送两次上游请求，流式开始输出后不再重试。
- 除第一次明确模型不可用错误被成功回退替代外，上游错误的状态码、正文、内容类型、重试时间和请求标识均透传，回退后的错误也直接返回。插件本地错误、网络中断及超出响应大小限制的情况仍返回本地错误。
- 自动版本排序支持品牌名紧接数字（如 `qwen2.5`、`qwen3`），按完整数字段比较，`3` 和 `3.0` 视为同版本；忽略长日期编号。
- 当前模型、优先级和访问密钥持久保留；上游列表、不存在记录和刷新任务仅放内存。正常成功对话不额外查询列表，只记录模型切换日志。
